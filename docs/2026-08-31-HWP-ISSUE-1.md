# GitHub 이슈 #1 수정 보고 — HWP dry-run/apply·표·timeout

대상: `mororii/doc-bridge#1`, DocBridge 0.4.18

## 반영 결과

- A: HWP `GetTextFile("TEXT")`의 숫자 엔터티를 공개 읽기·길이·검색 전에 Unicode로 디코딩한다. `−`/`㎜` 원문과 `&#8722;` 입력을 실제 한글에서 검증했다.
- B: `hwp_apply_ops`/`hwp_submit_ops` 스키마에 최상위 `find`, `replace`, `scope`, `occurrence`, `matchCase`가 노출된다.
- C: 그림 수는 `$pic`과 최신 한글 `gso`를 합산하고 정확히 1개 증가해야 성공한다.
- D: 표 `HeadCtrl` 목록을 먼저 고정하고 같은 컨트롤 객체를 읽어 다음 표의 중복·누락을 방지한다. 각 표는 고유 `controlRef`를 반환한다.
- E: `hwp_submit_ops`와 `hwp_get_job`을 추가했다. 제출은 즉시 `jobId`를 반환하며 client timeout 뒤 중복 적용하지 않는다.
- F: 행·열은 항상 한 줄씩 실행하며, 각 회차의 실제 전체 셀 수 증감이 일정한지 확인한다. 구조 검증이 없으면 성공을 주장하지 않는다.
- G: `table_set_cells`(최대 500셀)를 추가했다. 표와 수식 위치를 한 번만 찾고 각 셀을 정확히 재읽는다. `includeStyles:false` 표 조회는 셀별 서식 COM 조회를 생략한다.
- H: `find_replace`에 전체 문서, 1부터 시작하는 `occurrence`, 문단 범위, 표 셀 범위를 추가하고 dry-run과 apply가 같은 시뮬레이션을 사용한다.
- I: 표 인벤토리에 `hasFormula`를 반환한다. `%fmu` 수식 셀은 일반 텍스트 덮어쓰기를 거부하고 구체적인 오류를 반환한다.

## 검증

- Release 빌드 경고 0.
- 오프라인 배포 게이트 Core 비-E2E 198 + MCP 19 통과.
- 실제 한글 전용 E2E의 정상 실행에서 Unicode 엔터티, 범위 찾기/바꾸기, 9×44 표와 뒤 2×2 표, 4셀 batch, 행 4개 삽입·삭제를 검증했다.
- 전용 테스트는 DocBridge가 만든 빈 문서만 사용하고 종료 시 닫아 사용자의 문서를 건드리지 않는다.

## 현재 PC 한글 시작 안정성 기록

- 동일 E2E를 새 COM 인스턴스로 반복하던 중 기능 op에 진입하기 전 `status`가 timeout되었고, 전용 한글 창 제목이 `오류`로 확인됐다.
- `hwp_doctor` 결과 이 PC는 한글 2024 `13.0.0.866`이며 권장 안정 패치 `13.0.0.3870`보다 오래됐다. TourPopup/FontCache 초기화가 불안정한 알려진 전제이므로 최신 한글에서 신선한 인스턴스 반복 E2E를 다시 통과해야 한다.
- 생산 경로는 직접 COM이 아니라 격리 worker를 사용한다. `getStatus`는 15초 제한, timeout 뒤 45초 회로 차단, 같은 쓰기 자동 재제출 금지로 빈 창 반복과 중복 적용을 막는다.
- 실패한 전용 테스트가 만든 HWP 프로세스만 PID를 확인해 종료했으며 사용자 문서와 사용자 소유 한글 프로세스는 종료하지 않았다.
