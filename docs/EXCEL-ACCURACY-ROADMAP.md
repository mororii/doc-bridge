# Excel 정확도·속도 중심 목표

2026-09-12 사용자 지시에 따른 최신 우선순위. 과거 인계의 거의 모든 Excel 기능 구현 및 복구 확장 우선순위보다 이 문서를 우선한다.

## 최종 목표

Excel 내부 대화 화면 없이, 연결된 AI와 DocBridge를 합쳐 Claude Excel 추가 기능에 준하는 업무 기능·정확도·속도를 제공한다. 자연어로 기존 통합문서를 이해하고, 셀 근거로 설명하며, 수식을 보존해 수정하고, 표·차트·피벗 보고서를 완성하는 전체 흐름이 대상이다.

사용자 범위 보정(2026-09-12): 글자·셀·행/열·시트·표·차트·도형의 생성·조회·편집·삭제 등 일상 실무 작업을 명시적인 기능 범위로 다룬다. 수식 분석과 읽기 개선만으로 실무 기능 동등성을 주장하지 않는다. 기존 구현의 공개 호출 경로를 확인하여 재사용 가능한 기능을 우선 활용하고, 연결·사용법 보완과 신규 구현을 구분한다. 상세 현황과 이번 작업 계획은 `EXCEL-PRACTICAL-SCOPE.md`에 기록한다.

## 진행 원칙

- 정확한 값·수식·참조·서식·집계 결과와 작업 완료 시간을 우선한다.
- 기존 보호장치를 유지하되 새 복구·스냅샷 체계 확대, 모든 장애 조합 시험, Excel 내부 UI는 이번 우선 범위에서 제외한다.
- 한 번에 검토 가능한 작은 개선 단위로 구현하고 검사한다. 같은 조건의 실패와 통과 검사를 이유 없이 반복하지 않는다.
- 전체 기능을 다시 만드는 대신 기존 구현을 활용한다. 미구현 고급 기능은 실제 업무 필요에 따라 추가한다.
- Hermes가 실행을 관리하거나 직접 구현하고 주 에이전트가 설계·최종 검증한다. 과거 실행자·dispatch는 재사용하지 않는다.
- 이후 회차는 hermesscop을 계속 적용한다. 착수 전 범위·작업량·예상 시간을 알리고, 실제 소요·완료량과 차이가 나면 추정을 갱신한다. 실제 Excel/Claude 검증 보류는 계속 유지한다.

## 구현 순서와 완료 근거

1. 대량 조회 정확도·속도: COM에서 읽기 전에 범위를 제한하고 누락 없는 페이지 조회, 정확한 셀 주소, 명시적 Formula2 읽기를 제공한다. 작은 범위의 호환성과 큰 범위의 완전성·타입 보존을 검증한다.
2. 수식·문서 이해: 시트 역할과 이름·표·수식 관계를 필요한 범위만 읽고, 오류 원인을 셀 근거로 설명한다. 알 수 없는 관계를 추측한 확정 결과로 반환하지 않는다.
3. 실제 업무 완수: 내역서 입력 변경과 재계산, CSV 정리, 표 확장과 피벗 갱신, 차트 보고서를 공개 API로 실행해 정답과 비교한다. 저장·재열기는 결과 지속성 확인에 사용한다.
4. 처리 속도: 동일 작업의 불필요한 호출·중복 읽기·셀별 COM 왕복을 줄인다. 소요 시간과 호출 횟수를 실제 측정하며 다른 작업의 속도 수치를 섞지 않는다.
5. 통합 검증·로컬 반영: 검토한 동일 소스의 빌드와 제품 경로를 검증한다. 설치 바이너리와 개발 후보를 구분한다.

## 비교 수락 기준

- 동일한 원본 복사본, 자연어 지시, 입력 변경, 독립 정답표를 사용한다.
- 정답률, 수식·셀 타입·서식 보존, 전체 완료 시간, 호출/재시도/사용자 개입 수를 기록한다.
- API 수준 시험과 자연어부터 시작하는 AI 전체 흐름 시험을 구분한다.
- Claude 직접 비교를 실행하지 못했으면 `비교 미실행`으로 표시한다. 자체 단위 테스트 통과나 도구 개수로 동등 성능을 선언하지 않는다.
- 속도 동등 여부는 같은 업무의 반복 측정으로 판단하며, 측정 전 임의 배수·완성률을 정하지 않는다.

## 현재 회차

사용자 진행 지침(2026-09-12): 실제 Excel/Claude를 실행하는 검증은 이후로 미룬다. 기능 구현과 빌드·코드 수준 테스트는 계속한다. 이 기간에 추가한 기능은 네이티브 검증 완료나 Claude 동등 성능으로 보고하지 않는다.

첫 변경 단위는 대량 조회의 범위 제한·페이지 처리·Formula2 읽기다. 증거는 작업공간 `output/docbridge-excel-accuracy-20260912/`에 기록한다. 최종 목표는 아직 달성 판정 전이다.

1차 개선 인수: 누락 없는 페이지 처리 20,736 조합, 실제 1,200셀 전수 조회, Formula2 읽기와 SEQUENCE 2x3 입력 결과를 확인했다. 특정 100만 셀 범위 요청의 값·수식 1만 셀 반환은 이전 후보 1.633초→0.875초(세 warm 표본 중앙값)였다. 전체 Claude 동등 성능이나 설치 완료를 뜻하지 않는다. 최종 결과와 남은 작업은 같은 증거 폴더의 RESULT.md에 있다.

2차 구현: `excel_inspect scope:formula_trace`, 제한된 참조 그래프와 오류 증거, 동적 배열 참조, 전체 행·열 참조, 기본 표 열 참조와 여러 시작 셀에 걸친 순환 참조 처리를 추가했다. 최종 Release 빌드 경고·오류 0, 수식 추적 코드 테스트 7개와 MCP 테스트 20개가 통과했다. 실제 Excel/Claude 검증은 사용자 지침에 따라 보류했다. 복합 표 선택자·현재 행 참조, 전체 업무 시나리오와 성능 비교는 남아 있다. 증거: `output/docbridge-excel-reasoning-20260912/RESULT.md`.

4차 구현: 수식 추적의 값·수식 읽기를 제한된 사각 범위로 묶고 요청별 셀 캐시를 추가했다. 겹치는 읽기 재사용, 긴 열의 수직 병합, 배열 모양 불일치의 불완전 표시를 코드로 확인했다. 최종 Release 빌드 경고·오류 0, 전체 Core 테스트 959개와 MCP 테스트 20개가 통과했다. 모의 범위 호출 수 감소는 실제 Excel 시간 단축 측정과 구별한다. 기존 입력·CSV·표/피벗·차트 기능의 효율적인 조합 지침은 `skills/document-automation/references/excel-workflows.md`에 있다.
