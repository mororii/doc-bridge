# 2026-08-12 DocBridge 피드백 및 조치

## 확인된 결함

1. `table_insert_rows/columns`와 `table_delete_rows/columns`의 `count` 계약 불일치
   - 삽입은 한글의 `HTableInsertLine.Count`에 값을 한 번 넘겨 일부 한글 2024 빌드에서 1줄만 처리됐다.
   - 삭제는 `count`를 읽지 않아 항상 1줄만 삭제했다.
2. `insert_before_text`/`insert_after_text`의 Unicode readback 오판
   - `−`(U+2212), `㎜`(U+339C)가 포함된 긴 문단은 입력됐어도 HWP TEXT readback이 `−`를 리터럴 `&#8722;`로 직렬화해 롤백됐다.
   - 표 셀 쓰기 경로와 달리 상대 문단 삽입 검증만 원문을 ordinal 비교한 것이 원인이었다.
3. `dryRun`이 같은 배치의 op를 순차 시뮬레이션하지 않았다.
   - 첫 op가 만든 문구나 표를 뒤 op가 참조하면 실제 적용은 가능해도 미리보기에서 0 occurrence/표 없음으로 판단할 수 있었다.
4. 표 셀에 그림을 직접 넣는 공개 입력 계약이 없었다.
5. 문서 탭 활성화 COM 호출이 길어질 때 작업 경계 사이에서 한글 창이 잠시 전경에 남을 수 있었다.

## 반영 내용

- 표 행·열 삽입/삭제는 `count`만큼 대상 셀을 다시 지정해 한 줄씩 실행한다. 가능한 한글 버전에서는 전후 `rowCount`/`columnCount`도 읽고, 이를 노출하지 않는 빌드에서는 회차별 재선택·단일 액션 성공과 경계 셀 표식 readback으로 검증한다.
- 상대 삽입 검증에만 HTML 숫자 엔터티 디코딩, Unicode NFKC와 대시/수학 마이너스 등가 정규화를 사용한다. 문서에 쓰는 원문은 변경하지 않는다.
- 미리보기는 본문과 표 개수·행·열을 op 순서대로 누적한다. 앞 op가 만든 anchor, 표, 행·열을 뒤 op가 즉시 참조할 수 있다.
- `insert_picture`가 `tableIndex`와 `row+col` 또는 `cellIndex`를 받는다. 표 셀 기본 크기는 `cell-ratio`, `clearCell` 기본값은 `false`다.
- 실제 Win32 실행에서는 30ms 전경 감시를 추가하고, 한글 탭을 내부 활성화한 직후에도 즉시 원래 전경 창을 복구한다.

## 회귀 검증

- Core 144건, MCP 17건 통과.
- Unicode `−`/`㎜` 등가 readback과 오인 방지 반례 테스트 추가.
- append 뒤 상대 삽입, 두 번째 occurrence 인라인 삽입 순차 시뮬레이션 테스트 추가.
- 공개 MCP 스키마에 `count`, `position`, 그림 `path`, `sizeOption`, `clearCell` 노출 여부 테스트 추가.
- 실제 한글 선택 E2E에 4행 삽입 후 새 5·6번째 행 표식 입력, 4행 삭제 후 삭제 경계 표식 제거·다음 행 표식 보존 검증 추가.
- 실제 한글에서 `−`·`㎜`가 섞인 404자 문단 상대 삽입과 전체 readback 검증 통과.
- 실제 한글에서 지정 표 셀 사진 삽입·대상 주소·그림 control 증가 검증 통과.
- 실제 한글 dry-run에서 앞 op가 만든 anchor와 표를 뒤 op 3개가 순서대로 참조하는 네 단계 미리보기 검증 통과.

## 남는 제약

- 한글 Automation은 문서 탭을 내부 활성화해야 하는 작업이 있다. 전경 복구는 창 노출 시간을 최소화하지만 사용자가 같은 한글 문서를 동시에 편집하는 것은 지원하지 않는다.
- 구버전 한글에서 표 컨트롤의 행·열 속성을 제공하지 않으면 종료 조건이 불명확한 전체 셀 순회로 수치를 추정하지 않는다. 각 1회 액션 성공 횟수와 요청 범위의 경계 셀 readback으로 검증한다.
