# DocBridge 0.4.21 — Excel 서식 적용과 CAD·한글 읽기 개선

2026-09-10 · Windows x64 · Excel / 한글 / AutoCAD / GstarCAD

버전은 **0.4.21**입니다. 이 문서는 공개 동작 계약과 확인된 실측을 정리합니다.
아래 「확인된 실측」과 「검증 범위」의 숫자·시나리오는 버전을 올리기 전 **구현 빌드**의
순서 있는 과거 표본입니다. 버전을 맞춘 뒤의 로컬 패키지·설치·패키지 CLI 왕복은
「0.4.21 로컬 릴리즈 검증」에 따로 적습니다. GitHub CI와 공개 ZIP은 소스 푸시 뒤에
확인하며 이 문서는 그 통과를 주장하지 않습니다. 파일 해시나 내부 경로는 넣지 않습니다.
0.4.20 이전의 계약과 기록은 [RELEASE-0.4.20.md](RELEASE-0.4.20.md)에 그대로 있습니다.

## 이번 변경 요약

- **Excel 지연 서식 체크포인트**를 실제 execute 경로(호스트와 CLI worker)에 추가했습니다. 기본값은 꺼져 있고 정확한 opt-in입니다.
- **보조 workbook 사본**의 출처를 metadata에 명시하고, 저장 전 메모리 상태 사본을 선택적으로 켤 수 있게 했습니다.
- **CAD**는 객체당 중복 COM 속성 읽기 7회를 제거했습니다. 기존 지문은 그대로입니다.
- **한글**은 필요한 문단 수를 넘는 지도 생성을 멈추고, 전체 텍스트 읽기 실패를 성공으로 숨기지 않습니다.

## Excel 지연 서식 체크포인트 (opt-in, 기본 OFF)

### 무엇을 바꾸는가

적용 전 서식 상태를 **어디서 읽는지**만 바꿉니다. 무엇을 복원하는지, 무엇을 검증된 롤백으로
볼지, 기본 동작과 dry-run의 의미는 그대로입니다. 비싼 셀별 COM 읽기를 캡처 시점이 아니라
**롤백이 실제로 필요할 때**로 미루고, 그 대신 캡처 시점에 저장 전 메모리 상태를 체크포인트
파일로 복사합니다. 복구할 때는 그 사본에서 **해당 작업이 바꾼 서식만** 읽어 원본 워크북에
되돌립니다.

- **전체 워크북을 덮어쓰지 않습니다.** 체크포인트 이후에 입력한 값·수식·대상 밖 서식은 그대로 유지됩니다.
- **사용자 승인 단계를 추가하지 않았습니다.** 기존 execute 흐름을 그대로 이용합니다.
- **정상 적용이 빨라지는 대신 복구가 느려집니다.** 아래 실측처럼 비용이 사라지는 것이 아니라 캡처에서 롤백으로 옮겨갑니다. 복구를 매번 수행하는 작업에는 이득이 없습니다.

### 켜는 방법과 적용 조건

환경변수 `DOCBRIDGE_EXCEL_DEFERRED_FORMAT_SNAPSHOT=1`을 설정한 경우에만 후보가 됩니다.
정확히 `1`만 활성이며 `true`/`yes`/`01`/공백이 섞인 값은 활성이 아닙니다. 설정하지 않으면
기존 eager 스냅샷 경로가 그대로 쓰입니다.

후보 조건은 좁습니다.

- **execute 경로**에서만 검사합니다. dry-run, confirm 재사용, `core_create_snapshot`은 대상이 아닙니다.
- 단일 `format_range` 배치, 명시한 `target.sheet`, 단일 직사각형 A1 범위, `fillColor` 포함.
- 대상 셀 **1,000~5,000개**. 원본과 체크포인트가 **각각 16MiB(16,777,216바이트) 이하**.
- 로컬 일반 `.xlsx`(`FileFormat` 51). UNC/URI 경로는 제외합니다.

작은 편집과 균일 Bold 전용 작업은 기존 빠른 경로가 이미 싸므로 대상이 아닙니다. 이 범위는
최적 교차점 주장이 아니라 보수적인 롤아웃 한계입니다.

### 제외 대상과 되돌아가는 방식

**모든 수식**은 제외합니다. 대상 범위 안이든 밖이든, 다른 시트에 있든, 값이 캐시되어 있든
상관없습니다. 매크로/VBA, 외부 연결, 연결·쿼리, OLE/ActiveX, 보호·암호, 병합, 서식 있는
텍스트, 지원하지 않는 RGB+tint, 이름 정의·조건부 서식·데이터 유효성도 제외합니다. 평문 데이터
파트 어휘 밖의 파트는 모두 제외이며, 여기에는 **웹 추가 기능(Office 추가 기능) 파트**가
포함됩니다. 추가 기능이 화면에 보이지 않거나 사용자가 쓰지 않아도 파트가 패키지에 들어 있으면
제외입니다.

자격 거절은 요청·워크북·체크포인트 바이트 세 단계 모두 apply보다 앞에 있으므로
**워크북에 아무것도 쓰기 전에** 기존 eager 경로로 되돌아갑니다. 부분 적용 뒤에 경로가 바뀌는
일은 없습니다. 거절 사유는 스냅샷 metadata에 code와 문장으로 남습니다.

한 가지는 되돌아가지 않습니다. 체크포인트 **사본을 시도한 뒤** 워크북의 경로·저장 플래그·열린
워크북 수를 다시 읽어 비교했을 때 **그대로임을 확인하지 못하면**(값이 달라졌거나 이번에는
읽히지 않으면) 대체 경로로 내려가지 않고 스냅샷 자체를 거절해 그 편집이 진행되지 않게 합니다.
신원을 확인하지 못한 워크북에 쓰기를 이어 가지 않기 위해서입니다. 반대로 사본을 시도하기
**전에** 그 값을 다 읽지 못한 경우는 사본을 만들지 않은 채 기존 경로로 되돌아가는 평범한
자격 거절입니다.

### 복구 조건과 구버전 동작

- **크래시 복구가 아닙니다.** 복구는 Excel과 대상 워크북이 **살아 있는 세션**을 요구합니다. 호스트 프로세스는 새로 떠도 되지만(새 CLI 프로세스에서의 복구는 검증했습니다) Excel이 다시 뜬 상황은 복원하지 않습니다. 응답의 `deferredRestoreRequiresLiveSession=true`가 이를 명시합니다.
- 추출이 실패하면 성공으로 보고하지 않습니다. 체크포인트 파일은 증거로 남기고, "롤백이 돌았지만 불일치"와 "롤백을 재구성조차 못함"을 구분해 알립니다.
- 구버전과의 호환은 **거절**로 처리합니다. 새 스냅샷은 구버전이 아는 형식에 지원하지 않는 버전을 기록하므로, 구버전 바이너리는 워크북을 **바꾸기 전에** 거절합니다. 정확한 조합을 처리하는 것은 새 코드뿐입니다.

계약의 전체 code 목록과 세부 동작은 [EXCEL-OPERATIONS.md](EXCEL-OPERATIONS.md)에 있습니다.

## 확인된 실측 (구현 빌드, 과거 순서 표본)

같은 생성 파일에서 기존 방식의 적용·복구를 먼저, 이어서 새 방식의 적용·복구를 측정했습니다.
제품 호출 시간이며 테스트 준비·앱 실행·별도 전수 검사는 제외합니다. 복구는 확정 호출만
포함합니다.

| 대상 | 기존 적용 | 새 적용 | 기존 복구 | 새 복구 |
|---|---:|---:|---:|---:|
| 1,000셀 (18,981바이트) | 7.235초 | 0.113초 | 9.021초 | 15.736초 |
| 5,000셀 (52,369바이트) | 24.206초 | 0.124초 | 39.175초 | 60.805초 |

- 적용+복구 합계는 1,000셀에서 16.256 대 15.849초, 5,000셀에서 63.381 대 60.929초로 서로 가깝습니다. 이 표본이 보여 주는 것은 총량 감소가 아니라 **캡처에서 롤백으로의 비용 이동**이며, 이득은 복구를 실제로 얼마나 드물게 하는지에 달려 있습니다.
- 각 규모마다 **순서가 있는 단일 표본**입니다. 기존 방식 다음에 새 방식을 측정했으므로 캐시·순서 효과를 포함합니다. p50/p95가 아니고, 모든 워크북·모든 장비에 통하는 속도 배율도 아닙니다. 같은 조건의 기존 적용이 다른 표본에서 5.560초로도 측정되어 표본 간 변동이 작지 않습니다.
- 의도적인 부분 실패 시험의 자동 복구는 1,000셀 13.773초, 5,000셀 70.980초였고 각각 대상 셀 전체의 원래 서식이 복구됐습니다. 셀 한도와 STA 120초는 올리지 않았습니다.
- 작은 생성 파일 표본의 통과이며 모든 환경의 복구 시간 보장이 아닙니다.

수치의 분해와 한계는 [PERFORMANCE.md](PERFORMANCE.md)에 있습니다.

## 검증 범위 (구현 빌드, 과거)

통과한 것만 통과라고 적습니다.

- 제품 Release 빌드 경고 0·오류 0, 비-E2E Core 631, MCP 20.
- Excel 1,000셀 실제 앱 시나리오 7종: 정상 적용·명시 복구, 실제 부분 실패의 자동 복구, 손상된 체크포인트 거절, CLI worker 메타데이터 전달과 새 CLI 프로세스에서의 복구, 구버전 거절, 기존/새 방식 비교, 수식 파일에서 기존 경로로의 전환과 그 복구.
- Excel 5,000셀 2종: 기존/새 방식 비교와 실제 부분 실패의 자동 복구. 대상 5,000셀 서식 전수 비교 불일치 0.
- **체크포인트 이후에 입력한 값·수식·표시 형식이 보존되는지는 1,000셀 정상 사례와 1,000셀 CLI 사례에서만 확인했습니다.** 5,000셀 시험은 서식 복원과 부분 실패 복구이며 그 보존 검사를 포함하지 않습니다.
- 구버전 거절은 설치본 0.4.18, 이전 로컬 후보 빌드, 그리고 **GitHub에서 내려받은 공개 0.4.20 바이너리** 세 가지에서 실제로 통과했습니다. 공개 ZIP은 릴리즈 자산 SHA-256과 일치함을 먼저 확인했습니다.
- 이전 단계의 AutoCAD/GstarCAD native 4건과 한글 native 3건(PDF 시각 검사 포함)은 그대로 유지됩니다. 해당 어댑터와 테스트 파일이 그때와 같음을 다시 확인했습니다.

주장하지 않는 것:

- **웹 추가 기능 파트(`complex-part`)를 통한 기존 경로 전환은 실제 앱에서 확인하지 못했습니다.** 실제 Excel이 만든 파일에 그 정보가 들어 있어 바이트 검사에서 거절된 실행도 있었고, 다른 실행에서는 새 파일에 없었습니다. 시작 상태에 따라 달라지므로 재현 가능한 시험 파일이 아니며, 전환 자체는 재현 가능한 수식 파일로 검증했습니다.
- 위 구현 빌드 표·시나리오는 버전을 올리기 전 기록입니다. 버전을 맞춘 뒤의 로컬 패키지·설치·패키지 CLI 왕복은 아래 「0.4.21 로컬 릴리즈 검증」에 있습니다. GitHub CI와 공개 ZIP 통과는 주장하지 않습니다.
- 호스트 크래시 뒤 Excel 잔류는 반증 전까지 미해결입니다. 이번 변경은 그 문제를 다루지 않습니다.

## 그 밖의 변경

- **보조 workbook 사본**: 기본값은 마지막으로 저장된 디스크 파일 복사이며, metadata가 출처와 저장 상태를 명시하므로 사본이 최신인지 추측하지 않아도 됩니다. `DOCBRIDGE_EXCEL_FRESH_WORKBOOK_BACKUP=1`(정확히 `1`)일 때만, 일반 `.xlsx`이고 저장 전 변경이 있는 경우에 한해 저장 전 메모리 상태를 복사합니다. 이 사본은 운영자용 증거 파일이며 자동 복원에 쓰이지 않습니다. 비용과 안전 조건은 [PERFORMANCE.md](PERFORMANCE.md)에 있습니다.
- **CAD**: 객체당 중복 COM 속성 읽기 7회를 제거했습니다. 기존 지문 값은 바뀌지 않습니다. 미지원 GstarCAD 기능은 여전히 검증 범위가 아닙니다.
- **한글**: 필요한 문단 수를 넘는 문단 지도 생성을 멈춥니다. 전체 텍스트 읽기가 실패하면 실패로 보고하며 빈 성공으로 숨기지 않습니다. 앱 시작 시간의 변동이 해결됐다고 보지는 않습니다.

## 0.4.21 로컬 릴리즈 검증

버전 문자열을 0.4.21로 맞춘 뒤 이 PC에서 통과한 로컬 게이트다. 위 구현 빌드 표·시나리오와 합산하지 않으며, 새 시간 표를 만들지 않는다. GitHub CI와 공개 ZIP 통과는 [Actions](https://github.com/mororii/doc-bridge/actions)와 [Releases](https://github.com/mororii/doc-bridge/releases)에서 푸시 이후 상태를 확인한다. 이 절은 그 통과를 주장하지 않는다.

- 통합 Release `-warnaserror` 경고 0·오류 0.
- 비-E2E Core 659, MCP 20. CI와 같은 필터 `FullyQualifiedName!~E2ETests&Category!=E2E`. 구현 빌드 Core 631과의 28건은 `HwpE2EOwnershipTests` 순수 단위 테스트가 예전 더 넓은 E2E 이름 필터에 걸려 빠졌던 것이다.
- 버전 일치·초보자 가이드 검증 통과. 공개 소스 검사 222파일에서 자격 증명·개인 자료 없음, 추적 PowerShell 19파일 구문 통과.
- win-x64 자체 포함 패키지 생성, 체크섬 407개 전수 일치, 빌드 PC·프로필 개인 경로 검사 통과.
- 가짜 사용자 폴더에서 설치·진단·제거 수명주기 통과.
- 패키지 CLI 1,000셀 실제 Excel 왕복 45.999초 통과. worker가 지연 서식 메타데이터를 전달했고, 다른 CLI 프로세스에서 복구했으며, 대상 1,000셀 원래 서식 전수 일치, 이후 입력한 셀 값·수식·표시 형식과 다른 시트 내용 유지, 원래 Excel 세션 설정 유지, 소유 Excel 종료 후 잔류 없음.

기본값은 꺼져 있다. 후보 조건, 수식·복잡 파트 제외, 살아 있는 세션 복구 제한은 위 계약과 같다. 웹 추가 기능 파트의 실앱 전환 확인과 호스트 크래시 뒤 Excel 잔류는 이 게이트로 해소되지 않았다.

## 업그레이드와 사용 지침

- 설치 절차는 [INSTALL.md](../INSTALL.md)를 따릅니다. 기본 동작은 0.4.20과 같으므로 환경변수를 설정하지 않으면 이번 Excel 변경은 경로에 들어오지 않습니다.
- 지연 체크포인트를 켜려면 서버를 실행하는 환경에 `DOCBRIDGE_EXCEL_DEFERRED_FORMAT_SNAPSHOT=1`을 설정하고 클라이언트를 다시 시작합니다. 값이 정확히 `1`이 아니면 켜지지 않습니다.
- 켤 만한 경우: 1,000~5,000셀 단위의 `fillColor` 서식 배치를 자주 수행하고, 워크북이 작으며, 롤백이 드문 작업입니다.
- 켜지 않는 편이 나은 경우: 롤백을 자주 수행하거나, 워크북이 크거나, 수식·추가 기능·보호가 있는 파일이 대부분인 작업입니다. 이 경우 조건에서 걸러져 기존 경로로 돌아가므로 이득도 없습니다.
- 이전 버전이 만든 스냅샷은 그대로 복원됩니다. 반대로 이번 형식의 스냅샷을 구버전 바이너리로 복원하려 하면 워크북을 바꾸기 전에 거절됩니다.
