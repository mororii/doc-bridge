# DocBridge document automation

Use this skill when the user asks to inspect or change a local Excel workbook, Hancom HWP/HWPX document, or AutoCAD drawing.

## Tool availability gate

1. Confirm that `core_get_status` and the requested app's `*_get_active_context` and `*_apply_ops` tools are available before inspecting project files or planning a write. For HWP also require `hwp_doctor`; for a new HWP document require both `hwp_plan_creation` and `hwp_launch`.
2. If any required DocBridge tool is missing or `core_get_status` cannot be called, stop the app-editing workflow. Do not create substitute scripts, patch the user's project, edit HWP/DWG internals, use UI automation, or silently switch to another mechanism.
3. Report that the DocBridge plugin is not loaded. Tell the user to run `2-TEST.cmd`, fully restart the AI client, and start a new task. Resume only after the required tools are visible.
4. Use standalone file editing only when the user explicitly requests that separate fallback after the missing-tool report. This never authorizes an automatic Excel bypass, direct Excel COM, shell/UI launch, or silent overwrite of the original workbook.

## Safety contract

1. Call `core_get_status` before app-specific work and report connection problems plainly. When only one app is in scope, pass `app`. Do not force `core_ping`, an all-app status, repeated context, a full-document reread, or a separate approval question on every write.
2. For Excel, inspect `apps.excel.connected` and `apps.excel.document` in that response before calling `excel_get_active_context`. Call the context tool only when `connected:true` and `document` is non-empty. If either check fails, do not use the context tool as a launch/probe and do not repeat it in a retry loop. Retry only after an observable state change, such as the user opening a workbook and a fresh status response showing its document.
3. `allowOpenFile` defaults to `false`. Use `allowOpenFile:true` with an absolute workbook path to an existing file only when the user explicitly asked to read that closed file. Never use it for writes, infer it from a generic Excel request, invent a path, or search for a substitute workbook. If the requested write requires an open workbook, report that requirement instead of launching a blank Excel instance.
4. If a DocBridge Excel call fails or reports a limitation, preserve and report the original DocBridge error, then stop. Do not fall back to `openpyxl`, `pywin32` or `DispatchEx("Excel.Application")`, PowerShell Excel COM, `Start-Process`, shell/UI automation, or repeated on-disk workbook overwrite. Resume only after an observable state change or the user explicitly selects a supported DocBridge route; an explicit request does not convert those bypasses into DocBridge work.
5. Read the needed range or document ref before proposing a change. Do not require a full reread when the apply response already has `readback`.
6. The user's request authorizes that scope. Distinguish client permission UI, server preflight, and human scope approval. Do not ask for re-approval on every write. An already-requested save or PDF does not automatically require a new question. `highRiskConfirm` does not bypass permission UI and does not prove human approval.
7. Allowlisted ordinary edits use one `*_apply_ops` call with `executionMode: "execute"`, a new UUID `requestId`, and `expectedDocumentRef`. Do not include `dryRun`, `confirmToken`, or `highRiskConfirm` even as false. Excel: `set_values`, `set_formulas`, `format_range`. HWP: current `autoExecuteOps` from policy/capabilities (`insert_text` is not included). CAD/GstarCAD: `set_text_value`, `set_layer_visibility`, `set_layer_color`, `regen_document` only. Reuse the same UUID only for a transport retry of the same work. Same UUID + app + document + ops replays the stored result; a different payload is denied. If `outcomeUnknown`, inspect the document before any new UUID.
8. Excel/CAD/GstarCAD execute requires a saved absolute path. The current adapters do not issue instance-bound refs. Bare `Book1`/`Drawing1` stay on the token path; do not auto-save to invent a path. A dirty CAD broad-operation or save fingerprint mismatch is denied; do not auto-save or bypass it. HWP uses the returned `documentRef`/`instanceRef` as-is.
9. Preview, high-risk, merge/visibility, geometry, delete, save, export, and document activation stay on `dryRun: true` then the same `ops` plus `confirmToken`. Inspect the returned diff. Do not treat a dry-run as an applied change. Ask again only if the diff materially exceeds the request or the target is ambiguous.
10. Set `highRiskConfirm: true` only on the token path after explicit approval for HWP table row/column deletion or PDF export, and for CAD delete operations, save/SaveAs, PDF plot, or registered script templates.
11. Check `readback.verified`, mismatches, warnings, errors, per-step `operationResults`, and `timings` after applying. For HWP, use `readback.postEditReread` when present as the authoritative state for the next edit and never reuse stale pre-edit positions. If fingerprint validation reports that the document changed after dry-run, reread and create a new dry-run instead of retrying the old plan.
12. After an Excel path-only workflow or any status whose detail is `DocBridge가 생성한 인스턴스`, verify that no unsaved change remains and call `excel_disconnect`. Owned saved workbooks are cleaned up on normal disconnect and worker pipe EOF. Crash leftovers remain observed; do not claim leftover-free Excel. Do not quit or force-kill a user-owned Excel instance; DocBridge disconnect releases only its COM reference in that case.
13. Restore snapshots only through the two-call confirmation flow exposed by `core_restore_snapshot`.

## Inactive-window and concurrency contract

1. DocBridge edits through the application's COM object model and preserves the user's current foreground app. Do not bring Excel, HWP, or AutoCAD forward with UI automation, mouse/keyboard control, or shell activation.
2. HWP may internally activate the requested document tab and CAD may internally activate a requested drawing/layout because their application-level APIs require it. DocBridge restores the original HWP document, caret, and selection, and the original CAD drawing, layout, model/paper space, before returning. Excel restores the original workbook and worksheet if a copy operation changes them.
3. The user may continue working in a different application while DocBridge runs. Simultaneous human and AI editing inside the same target Excel/HWP/CAD window is not supported.
4. Inspect the returned `interaction` object. If `userActivityDetected:true`, `interrupted:true`, or `[APP_USER_ACTIVITY_DETECTED]` appears, do not retry the old operations. Reread the target after the user leaves that app, create a fresh execute or dry-run, and continue only the unapplied work.
5. `foregroundPreserved:false` or `originalStateRestored:false` is a verification failure. Report it and reacquire context before any further write.

Tokens are single-use, expire after five minutes, and are bound to the exact operation payload and document. If the document or operation changes, run a new dry-run.

## Excel formula context with fewer calls

For input/recalculation, CSV cleaning, table/pivot updates, or chart reports, read [Excel business workflows](references/excel-workflows.md) only when that workflow is needed.

- For a calculation or formula question, use the installed tool schema to check whether `excel_inspect` supports `scope:"formula_trace"`. If available, request the relevant result cells with explicit `workbook`, `sheet`, `range`, and practical `maxDepth`/`maxCells`. Request `compact:true` when the schema supports it: the root carries workbook context and edge endpoints become quoted sheet/cell strings. Use returned cell values, formulas, and dependency edges as evidence; do not read the entire workbook first.
- Cite `nodes[].sheet` and `nodes[].address`. `coverage.complete:false`, unresolved references, incomplete read evidence, and an error classification of `unknown` mean the explanation is incomplete. Request the specific frontier only when it matters to the answer; do not invent unseen dependencies or error causes.
- For larger raw reads, use the exposed `excel_read_range` paging options and follow the returned continuation. Keep `includeFormulas` and `formulaMode:"formula2"` only when formula evidence is needed. A bounded page is not the whole requested range.
- Tool availability and reference support depend on the installed build. Do not infer availability from this source skill or treat build/unit-test success as proof of native Excel behavior. Respect a user's decision to defer real application verification.

## App notes

- GstarCAD: use only `gstarcad_get_active_context`, `gstarcad_query_entities`, `gstarcad_apply_ops`, and explicit `gstarcad_launch`. Existing `cad_*` tools are AutoCAD-only; never substitute them. Check `core_get_capabilities({"app":"gstarcad"})` first. Execute is only `set_text_value`, `set_layer_visibility`, `set_layer_color`, `regen_document`. Geometry/save/export/delete/activation stay on the token path. A text-handle or layer-property snapshot can fully restore that scope; it is not a full-drawing restore. Geometry snapshots are a drawing-backup plus partial state and do not guarantee automatic restore. Hatch, cross-document copy, XREF, block insertion, layout editing, PDF plot, scripts and RGB are not yet supported. Tokens and snapshots are product-specific.

- Excel: use `excel_get_active_context` and `excel_read_range`; preserve formulas unless the user explicitly asks to replace them. Never rely on the active sheet for a write: include `target.sheet` in every sheet-scoped op, or use a sheet-qualified range such as `'매출 내역'!B2` for `set_values`, `set_formulas`, `format_range`, `merge_cells`, and `unmerge_cells`. If both forms are present, require the names to match. Before and after merge or visibility work, read the exact range with `includeLayout:true`; require complete coverage or split the read into smaller ranges, and inspect `mergedAreas`, `rowStates`, `columnStates`, and `sheetVisibility`. For styles, accept `bold`/`fontBold`, `italic`/`fontItalic`, `fillColor`/`interiorColor`/`fill`; reject alias conflicts, unknown keys, nulls, and invalid colors before snapshot. Dry-run `format_range` before is the live cell style, not the string `current`. `includeStyles:true` returns both alias families plus `fillPattern`; no-fill is Pattern=none, not Color=0. Keep `format_range`-only batches separate so v3 `written-properties` snapshot/fingerprint stay on the written styles; bold-only must not inspect or restore other colors or tints. Uniform bool/font size/NumberFormat may use a range fast path; mixed and color work must obtain the needed cell state and verify after restore. Legacy v2 format snapshots still restore. Mixed value/structure batches must take a fresh preview rather than a universal workbook fingerprint. Do not write through rich-text/mixed Font/Interior nulls, a partial merge that leaves the target, or a non-theme RGB font/fill/pattern color with nonzero tint (`EXCEL_FORMAT_UNSUPPORTED_RGB_TINT`); theme-linked tint is allowed. Do not invert RGB tint. After apply, inspect per-op `operationResults` (stage, HRESULT, skipped) and `rollback.verified`. Do not treat empty `errors` as success when mismatches exist. A protected-sheet Bold COM refusal also blocks rollback writes (`rollback.verified=false`); do not claim every failure restore succeeded. COM readback is not a visual-quality proof. Do not claim leftover-free `EXCEL.EXE` or a general speedup. A single uniform-Bold sample is not mixed-color performance or a p50/p95. Tokens bind to exact numeric identity (`1`/`1.0`/`1e0` equal; `1e-100` ≠ `0`); do not treat parser overflow of a finite JSON number as NaN/Infinity. Run a homogeneous nonoverlapping `merge_cells` batch or a homogeneous nonoverlapping `unmerge_cells` batch (not mixed with each other or with values/format). A 31-month header pair is one merge-only batch, e.g. `G5:H5`, `I5:J5`, … through 31 adjacent two-column merges on row 5; overlapping ranges get `[EXCEL_MERGE_BATCH_OVERLAP]`. Never merge when non-upper-left cells contain values/formulas or the range partially overlaps an existing merge. Keep `set_rows_hidden`, `set_cols_hidden`, and `set_sheet_visibility` in a visibility-only batch; they may be combined with one another but not with content, format, copy, or merge ops. Never hide the active or last visible sheet and never request `veryHidden`. `find_replace` may omit a sheet only when `target.scope:"workbook"`; `copy_sheet` is explicit through `sourceWorkbook`, `sourceSheet`, and optional `targetSheet`. Use JSON strings, not numbers, for identifiers longer than 15 digits. Use `excel_inspect` with `scope:"scan"|"objects"|"errors"|"diagnostics"` before complex workbook work or when Protected View, a modal dialog, object inventory, or formula errors matter. Use `copy_sheet` to copy a worksheet from another open workbook, including workbooks in a different Excel process. `delete_sheet` restore is a whole-sheet copy from a current SaveCopyAs or current last-saved backup; also rewrite captured other-sheet formulas/names/charts/pivots. Capture `=Data!A1+SUM(Items[Amount])`, same-workbook `'[owned.xlsx]원장'!A1`, and 3D `Data:Summary!A1`. Exclude only real backup/external file tokens, not every `[`. Refuse delete before mutation when a dependency cannot be captured. Do not treat used-range value/numberFormat/tabColor replay as full recovery, and expect prewrite reject when that backup is missing. `set_view`/layout snapshot activates the target sheet to read Zoom/gridlines, then restores the original active sheet, selection, and scroll so sheet B cannot inherit A's view. `set_values` keeps JSON types: ISO date strings stay text (not serial 46275) and `"123"` is not 123. Text writes use a temporary `@` then restore the original NumberFormat; `""` may normalize to blank. Keep public `numberFormat:"General"`; Korean Excel `0x800A03EC` on that write uses `NumberFormatLocal` from `International[26]` (`G/표준`) and does not drop or replace the requested format. `calculate` uses worksheet/range Calculate, not Workbook.Calculate. `set_formulas` defaults to legacy `Range.Formula`; Formula2 is opt-in. FILTER/SORT/UNIQUE do not need `spillRows`. Native spill property is `SpillingToRange`; a failed lookup is unknown, not a dest-sized scalar. Rollback clears dest plus newly owned spill BEFORE restoring the old Formula2; write counts are not restored-value proof. A blocked spill must not clear neighboring user cells. `auto_fill`/`copy_range` readback must cover the filled band and shifted relative formulas. `import_csv` bounds cells while parsing. Do not Quit an owned Excel that still has workbooks; Saved does not authorize Quit. Lifecycle restore with 0 checks is `unproven`, not complete; a lost preexisting bystander is `incomplete` and is not recreated. Do not claim native Excel complete before E1–E9 artifacts and local plugin reflection.
- Hancom HWP: run `hwp_doctor` before the first HWP edit. Continue when `state:"CHECK_PASSED"`; run `hwp_repair_typelib` only after explicit approval and then restart HWP and the AI client. Before creating any new HWP document, call `hwp_plan_creation`. A new general document must use its `docx-first` route: create and visually verify DOCX, then call `hwp_launch` with `creationMode:"docx-first"`, absolute `sourceFile`/new `outputFile`, `expectedPageCount`, `expectedTableCount`, and `requiredText`; require `summary.verification.passed:true`. Existing HWP/HWPX, HWP templates, native fields, complex merged tables, HWP-only objects, or exact original-layout preservation use `native-hwp`. Only that route may call `hwp_launch({"creationMode":"native-hwp","newDocument":true})`, exactly once. The runtime DOCX import path uses HWP FileOpen(OOXML), not Word COM. Call `hwp_get_active_context` and inspect every item in `summary.openDocuments`, which enumerates all visible HWP windows and tabs. Select the requested document by name, full path, or content; when more than one document is open, never assume the foreground tab is the target. Pass that item's `documentRef` to `hwp_read_text` and to every write op in the batch. `instanceRef` (`hwp:<PID>:<documentId>`) is also accepted as the `documentRef` value and is preferred when a Korean path is mangled by a shell or the same saved path is open twice. Never combine `file` and `documentRef`, and never mix document refs in one batch. Use the same absolute `file` path on every op only for explicit disk-file work. When text, stable `lineId`, and structure are all needed, prefer one `hwp_read_text` call with `scope:"bundle"` and `sections:["text","document_map","structure"]`; add `fields` or `tables` only when required. Use `append_text` for document-end content and `insert_before_text`/`insert_after_text` for anchors. Never switch to PowerShell/Python HWP COM because content is long or multi-paragraph. After each batch, base the next plan on `postEditReread`. Use `hwp-production-workflows` for formatted reports and plans.
- AutoCAD: use `cad_launch` only when no suitable running instance exists, then context/query tools. Drawing, hatch, modification, block attributes, layouts, viewports, save and plot use direct ActiveX COM; AutoLISP and UI driving are not used. Call `cad_get_active_context({"detailLevel":"basic"})` first. Basic deliberately does not enumerate layers or ModelSpace entities, so an empty `summary.layers` means "not inspected", not "no layers"; check `layerCount`, `entityCount`, `coverage`, `entitySummaryStatus`, and `nextActions`. Use `detailLevel:"summary"` only for the bounded 50-layer/500-entity sample. For complete data, follow `nextActions` into paged `scope:layers`, spatial `scope:window`, or up to 100 `scope:regions` checks. If any query returns `truncated:true` or a region reports `sampleCoverage.truncated:true`, continue through its returned `nextActions` before making completeness claims. Use `scope:layouts` before output. Prefer stable handles and layers. Use `cad-production-workflows`; for sewer plan/profile sheets also use `cad-profile-sheet-pipeline`.
- AutoCAD execute is the same four ops as GstarCAD. Geometry/save/export/delete/activation stay on the token path.
- CAD high-risk backups preserve the on-disk drawing plus restorable layer/text state; do not describe this as a full-drawing restore. Geometry changes may require reopening the backup copy if automatic state restoration is insufficient.

Keep operations narrowly scoped, split unrelated high-risk changes onto the token path, and surface truncated reads before making decisions from incomplete data.
