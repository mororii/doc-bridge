DocBridge로 Excel, 한글, AutoCAD를 다룰 때는 화면 클릭, 임의 PowerShell/Python COM, VBA, AutoLISP로 우회하지 말고 doc-bridge MCP 도구만 사용한다. 도구가 보이지 않으면 파일을 수정하지 말고 설치 진단을 요청한다.

Excel은 먼저 core_get_status의 apps.excel.connected와 apps.excel.document를 확인한다. connected=true이고 document가 비어 있지 않을 때만 excel_get_active_context를 한 번 호출한다. 연결이 없거나 document가 비어 있으면 excel_get_active_context를 실행·연결 확인용 probe로 호출하거나 반복 재시도하지 않는다. 사용자가 Excel에서 통합문서를 연 것처럼 실제 상태가 바뀐 뒤 새 core_get_status가 문서를 확인한 경우에만 다시 시도한다. allowOpenFile의 기본값은 false다. 사용자가 닫힌 파일 읽기를 명시적으로 요청하고 기존 파일의 absolute workbook path를 제공한 경우에만 지원 도구에 workbook과 allowOpenFile:true를 함께 전달한다. 일반 Excel 요청에서 추론하거나 쓰기에 사용하거나 경로를 추측하지 않는다. 쓰기에 열린 통합문서가 필요하면 빈 Excel을 실행하지 말고 그 요구사항을 알린다. 경로 기반 작업 뒤 또는 detail이 `DocBridge가 생성한 인스턴스`이면 저장되지 않은 변경이 없음을 확인한 다음 excel_disconnect를 호출한다. 저장된 소유 통합문서의 정상 disconnect/파이프 정리는 지원한다. 크래시 뒤 EXCEL.EXE 잔류는 관측된 한계이며 유령 프로세스가 해결되었다고 보지 않는다. 사용자가 연 Excel은 종료하거나 강제 종료하지 않고 DocBridge COM 참조만 놓는다. 보호 시트 Bold COM 거절은 롤백도 쓰지 못하므로 rollback.verified를 확인하고, 모든 실패가 검증된 롤백으로 끝난다고 보지 않는다.

DocBridge Excel 호출이 실패하거나 기능 제약을 반환하면 original DocBridge error를 그대로 보고하고 중단한다. `openpyxl`, `pywin32` 또는 `DispatchEx("Excel.Application")`, PowerShell Excel COM, `Start-Process`, shell/UI automation으로 우회하거나 원본 workbook을 디스크에서 반복 overwrite하지 않는다. 실제 상태 변화가 있거나 사용자가 지원되는 DocBridge 경로를 명시적으로 선택한 경우에만 다시 진행한다.

일반적인 사용자 편집 요청은 그 범위의 승인이다. 모든 쓰기마다 재승인 질문을 하지 않는다. highRiskConfirm은 권한 UI를 대체하거나 사람 승인을 증명하지 않는다. 한 앱 작업은 core_get_status의 app 필터와 필요한 범위 읽기로 시작하고 ping·전체 앱 조회·반복 context를 강제하지 않는다. Excel set_values/set_formulas/format_range, 한글 autoExecuteOps(insert_text 제외), CAD/GstarCAD set_text_value/set_layer_visibility/set_layer_color/regen_document는 executionMode=execute와 새 UUID requestId, 저장된 절대 경로로 한 번에 적용한다. Excel/CAD는 인스턴스 바인딩 참조를 쓰지 않는다. 한글은 반환된 documentRef/instanceRef를 그대로 쓴다. dryRun/confirmToken/highRiskConfirm을 execute와 함께 쓰지 않는다. Book1/Drawing1은 저장해 경로를 만들지 말고 토큰 경로를 쓴다. CAD dirty 광범위 작업이나 저장 지문 불일치는 거절이며 자동 저장으로 우회하지 않는다. 미리보기·고위험·병합/숨김/도형/삭제는 dryRun=true 후 같은 ops와 confirmToken으로 적용한다. outcomeUnknown이면 새 UUID로 재실행하지 말고 문서를 먼저 확인한다.

Excel 쓰기는 target.sheet 또는 '시트명'!A1을 반드시 명시한다. Excel 병합·행열 숨김 전후에는 excel_read_range(includeLayout=true)로 mergedAreas와 hidden/visibility 상태를 읽는다. merge_cells/unmerge_cells는 한 batch에 하나만 사용하고, visibility op는 값·서식·복사·병합 op와 섞지 않는다. 활성 시트나 마지막 표시 시트를 숨기거나 veryHidden을 새로 설정하지 않는다. HWP는 hwp_get_active_context의 openDocuments에서 documentRef/instanceRef를 확인하고 file과 documentRef를 동시에 쓰지 않는다. CAD는 interaction.interrupted 또는 userActivityDetected가 true이면 현재 도면을 다시 조회하고 새 dry-run을 만든다. 대형 CAD는 cad_get_active_context(detailLevel=basic)의 nextActions를 따르고, 표본이 필요할 때만 summary를 요청한 뒤 cad_query_entities의 layers, regions, window, text 또는 entityType 필터로 후속 조회한다.
