DocBridge 설치 및 사용설명서

이 문서만 보고 Codex·Claude·Kimi·Cursor에서 Excel·한글·AutoCAD를 연결하고 안전하게 작업할 수 있습니다.

Windows 10/11 64비트 · 초보자용 · 오프라인 설치 패키지
설치 전 준비설치설치 확인 AI별 실행법실제 작업법문제 해결

전체 순서 한눈에 보기

1ZIP 압축 풀기
ZIP 안에서 직접 실행하지 않습니다.
2프로그램 종료
AI와 Excel·한글·AutoCAD를 종료합니다.
3설치와 검사
1-INSTALL.cmd 후 2-TEST.cmd를 실행합니다.
4AI 재시작 후 명령
새 대화에서 연결 확인부터 시작합니다.
핵심: 설치는 한 번만 합니다. 이후에는 Codex·Claude·Kimi·Cursor에 평소처럼 한국어로 작업을 지시하면 됩니다.

1. 설치 전 준비

  1. ZIP 파일을 마우스 오른쪽 버튼으로 누르고 모두 압축 풀기를 선택합니다.
  2. ZIP 속성 아래쪽에 차단 해제가 보이면 체크하고 적용한 뒤 압축을 풉니다.
  3. Codex, Claude, Kimi, Cursor, Excel, 한글, AutoCAD를 모두 종료합니다.
  4. 회사 PC라면 프로그램 실행 제한 여부를 사내 전산 담당자에게 확인합니다.
다른 작업 중인 AI가 있다면: 그 작업이 끝난 후 해당 AI만 종료하고 설치해도 됩니다. 이미 열린 문서가 있다면 먼저 저장하십시오.
한글 2024 사용자: 먼저 DocBridge 0.4.10 이상을 설치해 AI가 누락한 windir/SystemRoot를 자동 복구하십시오. 한글 자체 안정성을 위해 한컴 자동 업데이트 2024도 권장합니다.

기본 설치 위치: %LOCALAPPDATA%\DocBridge

2. 설치하기

  1. 선택 사항: 0-VERIFY.cmd를 더블클릭해 패키지 검사 결과가 PASS인지 확인합니다.
  2. 1-INSTALL.cmd를 더블클릭합니다.
  3. 검은 창에 반드시 INSTALLATION SUCCESS가 표시될 때까지 기다립니다.
  4. 아무 키나 눌러 창을 닫고 Codex·Claude·Kimi·Cursor를 다시 실행합니다.
설치 프로그램이 자동으로 하는 일: DocBridge 실행 파일 설치, Claude Desktop/Kimi/Cursor 사용자 전역 설정 병합, 기존 설정 백업, 한글 자동화 보안 모듈 등록, Codex 앱 내부 CLI 탐색, Codex marketplace 등록과 플러그인 기본 활성화입니다. 기존의 다른 MCP 설정은 지우지 않습니다. Cursor 프로젝트별 .cursor\mcp.json도 변경하지 않습니다.

검은 창에 경고가 표시될 때

Claude Code 명령줄이 없는 경우에는 수동 등록 명령이 다음 폴더에 만들어질 수 있습니다. Codex marketplace 등록 자체가 실패하면 설치기는 INSTALLATION FAILED로 중단합니다. 등록은 되었지만 실행 중인 Codex가 아직 MCP를 다시 읽지 않았다면 재시작 안내가 [WARN]으로 표시될 수 있습니다.

%LOCALAPPDATA%\DocBridge\generated-configs

이 폴더의 claude_desktop_config.json, claude-code.mcp.json, kimi-mcp.json, cursor-mcp.json, codex-config.toml은 설치 대상 PC의 실제 실행 파일 경로로 생성됩니다. 배포 ZIP 안에는 제작 PC 경로가 든 dist\clients 설정을 넣지 않습니다.

그 경우 아래의 “AI별 최초 등록과 실행법”에서 해당 AI 항목만 따라 하면 됩니다.

INSTALLATION FAILED가 나오면: 아직 설치되지 않은 상태입니다. 2-TEST.cmd를 실행하지 말고, 설치 창의 위쪽 오류 문구가 보이도록 사진을 찍어 전달하십시오. ZIP 탐색 창 안에서 실행했다면 ZIP을 마우스 오른쪽 버튼으로 눌러 모두 압축 풀기를 한 뒤, 압축을 푼 폴더에서 다시 실행합니다.

3. 설치가 잘 되었는지 확인하기

  1. 2-TEST.cmd를 더블클릭합니다.
  2. 핵심 검사 항목에 초록색 [OK]가 표시되는지 확인합니다.
  3. 실패 항목이 없다면 아무 키나 눌러 창을 닫습니다.
  4. Excel 통합문서를 하나 연 뒤 2-EXCEL-LIVE-TEST.cmd를 실행합니다. 반복 컨텍스트가 안정적이면 PASS가 표시됩니다.
Excel 실동작 검사는 별도입니다. 기본 2-TEST.cmd는 사용자의 업무를 방해하지 않도록 Excel을 새로 실행하지 않습니다. 2-EXCEL-LIVE-TEST.cmd는 이미 열린 통합문서에서 읽기 전용 컨텍스트를 두 번 확인하며, 문서가 열려 있지 않으면 자동 실행하지 않고 실패합니다.

상세 진단 결과는 아래 파일에 저장됩니다.

%LOCALAPPDATA%\DocBridge\doctor-report.json
검사 결과뜻과 조치
[OK]정상입니다. 다음 단계로 진행합니다.
[WARN]대부분 수동 등록 또는 AI 재시작이 필요하다는 뜻입니다. 아래 AI별 설명을 확인합니다.
[SKIP]해당 AI 프로그램이 실제로 이 PC에 설치되지 않아 검사를 건너뛴 것입니다. Codex가 설치되어 있는데 CLI나 플러그인을 못 찾으면 SKIP이 아니라 FAIL입니다.
[FAIL]오류 문구와 doctor-report.json을 함께 전달해 점검을 요청합니다.

AI가 작업하는 동안 다른 프로그램을 사용해도 되나요?

네. DocBridge 0.4.18에서 AI는 Excel·한글·AutoCAD를 COM으로 내부 편집하면서 사용자가 보고 있던 다른 프로그램을 전경에 유지합니다. 한글 탭이나 CAD 도면·배치를 내부적으로 잠깐 전환해야 해도 작업 후 원래 문서와 화면 상태를 복원합니다.
  • AI가 한글을 편집하는 동안 웹브라우저·메일·다른 업무 프로그램을 사용하는 것은 괜찮습니다.
  • AI와 사람이 같은 Excel·한글·AutoCAD 창을 동시에 편집하면 안 됩니다. 충돌이 감지되면 DocBridge는 현재 단계 뒤의 작업을 중단합니다.
  • 결과의 interaction.interrupted 또는 userActivityDetected가 true이면 문서를 다시 읽고 남은 부분만 새 dry-run으로 실행해야 합니다.
  • foregroundPreserved:false 또는 originalStateRestored:false이면 추가 편집 전에 대상 문서와 현재 탭·도면을 다시 확인합니다.
Codex 필수 통과 항목: 현재 CLI에서는 Codex CLI discovery, Codex plugin CLI mode, Codex marketplace registered, Codex MCP visible and enabled가 모두 [OK]여야 합니다. 구형 CLI에서만 Codex plugin installed and enabled가 대신 표시됩니다. 설치 직후 MCP만 [WARN]이면 Codex를 완전히 재시작하고 새 작업을 연 뒤 다시 검사합니다.

4. AI별 최초 등록과 실행법

설치 프로그램이 자동 등록에 성공했다면 “수동 등록”은 건너뛰어도 됩니다. 등록 여부를 확인한 뒤 새 대화에서 첫 점검 문장을 입력하십시오.

Codex

최초 1회 1-INSTALL.cmd가 Codex 앱 안의 CLI까지 자동으로 찾아 marketplace를 등록합니다. 현재 Codex CLI에는 예전의 plugin add/list가 없으므로, 패키지 정책이 DocBridge를 기본 활성화합니다.

자동 등록이 실패하면 아래 파일을 메모장으로 열어 적힌 marketplace 등록 명령을 PowerShell에서 실행합니다. 이 파일에는 그 PC에서 발견된 Codex CLI의 절대 경로가 기록됩니다.

%LOCALAPPDATA%\DocBridge\generated-configs\install-codex.txt

Codex를 완전히 종료했다가 다시 실행하고 반드시 새 작업을 시작합니다. 이미 열려 있던 작업은 설치 뒤에도 예전 도구 목록을 유지할 수 있습니다. 새 작업의 플러그인 목록에서 DocBridge가 활성화됐는지 확인합니다.

첫 점검 문장:

@DocBridge를 사용해서 core_ping을 실행하고 Excel, 한글, AutoCAD 연결 상태를 확인해줘. 아직 문서는 수정하지 마.

@를 입력하면 나타나는 목록에서 DocBridge를 선택하는 것이 가장 확실합니다.

Claude

Claude Desktop

전체 설치가 끝났다면 별도 명령은 필요하지 않습니다. Claude Desktop을 작업표시줄 오른쪽 알림 영역까지 완전히 종료한 후 다시 실행하고 새 대화를 시작합니다.

Claude Code

PowerShell에서 등록 상태를 확인합니다.

claude mcp list

목록에 doc-bridge가 없을 때만 다음 명령을 최초 1회 실행합니다.

$DocBridgeExe = Join-Path $env:LOCALAPPDATA "DocBridge\codex-marketplace\plugins\doc-bridge\dist\doc-bridge-mcp.exe"
claude mcp add --transport stdio --scope user doc-bridge -- "$DocBridgeExe" --stdio

claude를 실행하고 Claude Code 안에서 /mcp를 입력해 doc-bridge 연결 상태를 확인합니다.

첫 점검 문장:

doc-bridge를 사용해서 core_ping을 실행하고 현재 열린 Excel, 한글, AutoCAD 문서 상태를 확인해줘. 수정하지 마.

Kimi

설치 프로그램이 %USERPROFILE%\.kimi\mcp.json에 DocBridge 항목을 자동으로 추가합니다. PowerShell에서 확인합니다.

kimi mcp list
kimi mcp test doc-bridge

목록에 doc-bridge가 없을 때만 다음 명령을 최초 1회 실행합니다.

$DocBridgeExe = Join-Path $env:LOCALAPPDATA "DocBridge\codex-marketplace\plugins\doc-bridge\dist\doc-bridge-mcp.exe"
kimi mcp add --transport stdio doc-bridge -- "$DocBridgeExe" --stdio

kimi를 실행하고 Kimi 안에서 /mcp를 입력해 연결 상태를 확인합니다.

첫 점검 문장:

doc-bridge를 사용해서 core_ping을 실행하고 현재 열린 Excel, 한글, AutoCAD 문서 상태를 확인해줘. 수정하지 마.
첫 테스트 주의: Kimi의 YOLO/AFK 자동 승인 모드는 사용하지 마십시오. 도구 호출 내용을 확인한 뒤 승인하는 방식이 안전합니다.

Cursor

설치 프로그램이 사용자 전역 %USERPROFILE%\.cursor\mcp.json을 백업한 뒤 mcpServers.doc-bridge만 추가합니다. 모든 프로젝트에 적용되는 전역 파일이며, 프로젝트별 <프로젝트>\.cursor\mcp.json은 자동으로 만들거나 바꾸지 않습니다.

Cursor를 완전히 종료했다가 다시 실행하고 Cursor 설정의 MCP 목록에서 doc-bridge가 활성 상태인지 확인합니다. 같은 이름의 서버가 프로젝트 설정에도 있으면 한쪽만 남겨 어느 설정이 적용되는지 명확히 합니다.

첫 점검 문장:

doc-bridge로 core_ping과 core_get_status를 실행하고 Excel, 한글, AutoCAD 연결 상태만 보여줘. 아직 수정하지 마.

안전 규칙 템플릿은 다음 위치에 설치됩니다.

%LOCALAPPDATA%\DocBridge\generated-configs\cursor
  • docbridge-user-rule.txt: Cursor Settings → Rules에 붙여 넣는 모든 프로젝트용 일반 텍스트
  • rules\docbridge-safe-automation.mdc: 필요한 프로젝트의 .cursor\rules에 선택적으로 복사하는 규칙

대형 CAD 도면이 일부만 보일 때:

cad_get_active_context(detailLevel=basic)로 도면 상태와 nextActions를 확인해줘.
표본 통계가 꼭 필요할 때만 detailLevel=summary로 다시 읽고,
전체 레이어는 cad_query_entities(scope=layers)로 조회한 다음
관로 레이어를 고른 뒤 scope=window 또는 scope=regions와 layer/text/entityType 필터로 후속 조회해줘.
반환 개수와 전체 개수도 함께 보여주고 아직 수정하지 마.
동시 편집 금지: Cursor와 Codex·Claude·Kimi가 모두 연결돼 있어도 같은 Excel·한글·AutoCAD 문서를 동시에 수정하지 마십시오. 한 작업의 readback이 끝난 뒤 다른 AI에서 문서를 다시 읽고 새 dry-run을 만듭니다.

5. 실제 문서 작업시키는 방법

제어할 프로그램과 문서를 먼저 열어 둔 뒤 AI에 지시합니다. AI와 대상 프로그램은 같은 Windows 사용자 화면에서 실행되어야 합니다.

권장 작업 순서

순서AI에 시킬 내용목적
1. 연결 확인core_ping과 현재 활성 문서 상태를 확인해줘. 수정하지 마.잘못된 문서 수정 방지
2. 대상 읽기현재 열린 문서와 선택 영역을 읽고 documentRef와 요약만 보여줘.작업 대상 확정

5. 다시 읽어 검증수정한 부분을 다시 읽고 요청대로 반영됐는지 확인해줘.결과 누락 방지

Excel 예시

DocBridge로 현재 활성화된 Excel 통합문서를 확인해줘.
원본 백업을 먼저 만들고, '고색-1구간' 시트의 비고란을 비운 다음
'유입부 120'은 '유입부 90'으로, '유입부 250'은 '유입부 180'으로 변경해줘.
모든 쓰기 op에 target.sheet='고색-1구간'을 명시하고 활성 시트를 추정하지 마.
먼저 dry-run 결과를 보여주고 적용 후 해당 셀을 다시 읽어 검증해줘.

최신 DocBridge는 Excel 쓰기에서 활성 시트를 자동 선택하지 않습니다. target.sheet 또는 '시트 이름'!B2 형식의 범위를 반드시 사용하며, 숫자는 Excel COM Double로 안전하게 전달합니다. 15자리보다 긴 번호는 문자열로 지시하십시오.

빈 회색 Excel 창 방지: 먼저 core_get_status를 확인하고 connected=true이며 document가 비어 있지 않을 때만 excel_get_active_context를 한 번 호출합니다. 경로만으로 닫힌 파일을 자동 실행하지 않습니다. 사용자가 닫힌 파일 읽기를 명시한 경우에만 절대 workbook 경로와 allowOpenFile=true를 함께 쓰며, 쓰기에는 사용할 수 없습니다. 실패 뒤 openpyxl, pywin32 DispatchEx, PowerShell Excel COM, Start-Process로 우회하지 않습니다.

셀 병합·숨김 작업을 안전하게 지시하는 방법

DocBridge 0.4.18은 셀 병합·병합 해제와 행·열·시트 숨김/표시를 지원합니다. 작업 전후에 같은 범위를 includeLayout=true로 읽으면 병합 영역, 숨겨진 행·열, 시트 표시 상태를 비교할 수 있습니다.

'고색-1구간' 시트의 B2:D2를 includeLayout=true로 먼저 읽어줘.
좌상단 외 셀에 값이나 수식이 없을 때만 merge_cells를 단독 batch로 dry-run 해줘.
diff와 snapshotId, confirmToken을 보여주고 내가 승인하면 같은 ops와 토큰으로 적용해줘.
적용 결과의 readback.verified=true를 확인한 뒤 같은 범위를 includeLayout=true로 다시 읽어줘.
  • 병합은 merge_cells, 병합 해제는 unmerge_cells이며 각각 한 batch에 단독으로 실행합니다. 병합 시 좌상단 이외 셀의 값이나 수식이 사라질 수 있으면 적용 전에 차단됩니다.
  • 행·열은 set_rows_hidden/set_cols_hidden의 hidden=true|false, 시트는 set_sheet_visibility의 visibility=hidden|visible을 사용합니다. 숨김 작업은 값·서식·복사·병합 작업과 batch를 분리합니다.
  • 현재 활성 시트나 마지막으로 보이는 시트는 숨길 수 없습니다. 통합문서 구조가 보호된 경우에도 변경하지 않고 이유를 알려줍니다.
  • 항상 사전 레이아웃 읽기 → dry-run → diff와 confirmToken 확인 → 승인 → 같은 ops 적용 → readback과 사후 레이아웃 확인 순서로 진행합니다.

0.4.15는 ActiveWorkbook/ActiveSheet와 컬렉션 Item()이 공유하는 COM RCW를 1회 균형 해제해 살아 있는 별칭이 분리되지 않게 합니다. 설치 후 Excel 문서를 열고 2-EXCEL-LIVE-TEST.cmd를 실행하면 같은 MCP 세션에서 활성 컨텍스트를 두 번 읽어 이 경로를 확인합니다.

Excel 연결을 끝내려면 “excel_disconnect를 실행해줘”라고 지시할 수 있습니다. 사용자가 열어 둔 Excel에는 Quit을 호출하지 않고 COM 참조만 놓습니다. DocBridge가 직접 만든 Excel만 저장되지 않은 변경이 없을 때 정상 종료합니다. Excel COM은 전용 worker가 소유하므로 AI가 비정상 종료돼도 파이프 EOF에서 같은 안전 정리를 수행합니다. core_get_status의 excel.detail에는 연결 종류가 표시됩니다.

DocBridge 0.4.18은 모든 표시 한글 창과 탭을 openDocuments로 열거하고, 선택한 documentRef 또는 instanceRef로 정확한 문서만 읽고 수정합니다. 별도 worker와 한글 COM 자식 프로세스에 검증된 windir/SystemRoot를 주입하고 한글 설치 Bin에서 활성화합니다. 텍스트 쓰기는 preserveStyle=true가 기본이며 적용 후 postEditReread로 문서 상태를 다시 읽습니다. 비활성 창 작업 중에는 탭 활성화 직후와 30ms 감시 주기로 원래 전경 앱을 복구하고, 한글 문서·커서·선택 영역도 원상태로 돌립니다.

복잡한 계획서·보고서·조직도는 hwp-production-workflows 스킬을 함께 지정하십시오. 한글 2024에서 숨은 창을 띄우는 셀 나누기·새 필드·북마크·하이퍼링크 삽입은 안정성을 위해 지원하지 않으며, 기존 양식 필드의 값 변경은 지원합니다.

7. 문제 해결

증상해결 방법
AI에서 DocBridge가 안 보임2-TEST.cmd를 먼저 실행합니다. 모두 OK면 AI를 완전히 종료한 뒤 다시 실행하고 새 대화를 만듭니다. 기존 대화에서 계속 시험하지 않습니다.
Codex 등록이 안 됨Codex marketplace registered 또는 Codex MCP visible and enabled가 FAIL인지 확인합니다. %LOCALAPPDATA%\DocBridge\generated-configs\install-codex.txt의 marketplace 등록 명령을 PowerShell에서 실행하고 Codex를 완전히 재시작한 뒤 새 작업에서 2-TEST.cmd를 다시 실행합니다.
Codex가 프로젝트 파일을 수정하며 우회함DocBridge 도구가 로드되지 않은 상태입니다. 그 작업을 중단하고 프로젝트 변경을 되돌린 뒤 설치 진단을 통과시키고 새 작업을 만듭니다. 도구가 없을 때 대체 스크립트나 LISP를 만들도록 지시하지 않습니다.
Claude Code 등록이 안 됨%LOCALAPPDATA%\DocBridge\generated-configs\install-claude-code.txt에 적힌 명령을 실행한 후 claude mcp list로 확인합니다.
Kimi 연결 실패kimi mcp test doc-bridge를 실행하고, 실패하면 수동 등록 명령으로 다시 등록합니다.
Cursor 연결 실패2-TEST.cmd의 Cursor global config와 MCP handshake를 확인합니다. `%USERPROFILE%\.cursor\mcp.json`의 doc-bridge.command가 현재 설치 EXE인지 확인한 뒤 Cursor를 완전히 재시작합니다.
Cursor 프로젝트에서 다른 MCP 설정이 적용됨프로젝트의 .cursor\mcp.json에 같은 doc-bridge 이름이 중복됐는지 확인합니다. 설치기는 사용자 전역 파일만 병합하므로 특별한 이유가 없으면 전역 구성 하나만 사용합니다.
Cursor에서 CAD 객체 상세가 바로 보이지 않음기본 cad_get_active_context(detailLevel=basic)은 대형 도면 성능을 위해 객체 순회를 생략합니다. 응답의 nextActions를 따르고, 제한 표본은 detailLevel=summary, 실제 조회는 cad_query_entities의 scope=layers, scope=regions, scope=window와 layer/text/entityType 필터를 사용합니다.
Excel 문서를 못 찾음Excel을 직접 실행해 대상 통합문서를 열고 excel_inspect(scope=diagnostics)로 제한된 보기·모달·수식 편집 상태를 확인합니다.
Cursor 작업 뒤 빈 회색 Excel 창이 남음구버전이 workbook 없는 context를 probe로 호출했거나 Cursor가 DocBridge 실패 뒤 openpyxl/DispatchEx/PowerShell COM으로 우회한 증상입니다. 최신판을 설치하고 Cursor를 완전히 재시작하십시오. 최신판은 status/context/dry-run으로 새 Excel을 만들지 않고, 명시적 allowOpenFile=true 읽기만 파일 열기를 허용하며 대체 COM·파일 덮어쓰기 우회를 금지합니다.
COM object ... separated from its underlying RCW0.4.14의 공유 RCW 과도 해제 오류입니다. 0.4.18 ZIP을 설치하고 모든 AI를 완전히 재시작한 뒤 Excel 통합문서를 열어 2-EXCEL-LIVE-TEST.cmd를 실행합니다. 두 번의 컨텍스트 검사가 모두 PASS여야 합니다.
Excel 창을 모두 닫았는데 EXCEL.EXE가 남거나 추가기능·매크로가 사라짐구버전 MCP가 Excel COM 참조를 보유한 증상입니다. 최신 ZIP을 설치한 뒤 Codex·Claude·Kimi·Cursor를 완전히 종료하고 다시 실행합니다. 최신판은 Excel COM을 전용 worker가 소유해 AI 강제 종료 시에도 파이프 EOF에서 DocBridge가 만든 Excel만 정상 회수합니다. excel_disconnect는 사용자 Excel을 종료하지 않고 연결만 해제합니다.
Excel이 엉뚱한 시트에 쓰거나 활성 시트만 사용함최신 배포본에서는 쓰기 op마다 target.sheet 또는 '시트 이름'!A1 범위가 필요합니다. 두 형식을 함께 쓰면 이름이 같아야 하며, 다르면 적용 전에 오류로 중단됩니다.
Value2 = Int32 캐스팅 오류최신 배포본은 셀 숫자를 Excel COM Double로 정규화합니다. 최신 ZIP을 다시 설치하고 AI를 완전히 재시작하십시오. 긴 식별번호는 숫자가 아니라 문자열로 입력합니다.
한글 연결 실패hwp_doctor를 실행해 CHECK_PASSED인지 확인합니다. TypeLib 오류이면 승인 후 hwp_repair_typelib을 실행하고 한글과 AI를 완전히 재시작합니다.
HWP runtime update recommended 경고DocBridge·TypeLib·자동화 환경은 정상이고 한글 패치만 권장된 상태입니다. ownedAutomationBlocked:false이면 계속 사용할 수 있으며 가능할 때 한컴 자동 업데이트를 실행합니다.
빈 한글 창이 반복해서 열렸다 닫힘DocBridge 0.4.10 이상을 설치합니다. 0.4.10은 한글 시작 환경을 먼저 복구하고, 실제 형식 초기화 오류창이 감지될 때만 같은 worker 호출의 재시도를 즉시 중단합니다.
PopupBorderImpl/TourPopup TypeInitializationException오류 창에서는 아니요(N)를 눌러 문서를 유지합니다. hwp_doctor에서 automationWindowsDirectory와 ownedAutomationBlocked를 확인합니다. 0.4.10 환경 복구 후에도 재현되면 한컴 자동 업데이트 2024를 실행합니다.
MS.Internal.FontCache.Util 또는 CultureFontManager 오류실제 내부 예외는 System.UriFormatException입니다. WPF가 windir\Fonts 절대 URI를 만들 때 AI 자식 환경의 windir가 없으면 발생합니다. 0.4.10은 worker와 한글 COM 시작 전에 windir/SystemRoot를 검증·복구합니다.
동일 한글 파일이 여러 창에 열렸다는 오류hwp_get_active_context.summary.openDocuments에서 원하는 창의 고유 instanceRef를 골라 documentRef 값으로 지정하거나, 중복 창이나 탭을 닫습니다. DocBridge는 잘못된 창을 임의 선택하지 않습니다.
HWP_COM_TIMEOUT한글의 팝업·대화상자를 닫습니다. worker는 자동 교체되므로 문서를 다시 읽고 갱신된 위치로 재계획합니다.
표에 넣은 글자의 폰트·정렬이 주변과 다름scope=tables, includeStyles=true로 대상과 반복 양식의 같은 라벨 값 셀을 먼저 읽게 합니다. 병합 표는 cellIndex로 지정하고, 적용 뒤 텍스트뿐 아니라 글자·문단 서식 메타데이터를 다시 비교합니다.
AI가 “다문단을 지원하지 않아 PowerShell로 전환”이라고 말함전환을 중단시키고 DocBridge의 append_text를 사용하게 합니다. 줄바꿈은 실제 한글 문단으로 보존되며, 길면 여러 DocBridge 배치로만 나눕니다.
PowerShell 또는 외부 VBA .bas의 한글이 깨짐배포 PowerShell 파일은 UTF-8 BOM으로 검사됩니다. 일반 DocBridge Excel 편집은 VBA를 쓰지 않습니다. 외부 VBA 교환이 꼭 필요할 때만 support\Convert-DocBridgeTextEncoding.ps1의 ConvertBasToCp949 모드로 CP949/CRLF 변환 후 가져옵니다.
AutoCAD 연결 실패AutoCAD와 도면을 연 뒤 명령 입력이 끝난 대기 상태에서 다시 요청합니다. 열려 있는 도면 이름도 함께 말합니다.
잘못된 문서가 선택됨즉시 적용하지 말고 창 제목·파일 경로·documentRef를 먼저 읽게 한 뒤 대상을 다시 지정합니다.
APP_USER_ACTIVITY_DETECTED 또는 작업이 중간에 안전 중단됨AI가 작업하는 대상 Excel·한글·AutoCAD 창을 사용자가 동시에 조작한 상태입니다. 해당 프로그램에서 손을 뗀 뒤 AI에게 현재 문서를 다시 읽고 완료된 단계와 남은 단계를 구분해 새 dry-run으로 이어서 작업하라고 지시합니다. 기존 confirmToken은 재사용하지 않습니다.
TEST NOT STARTED 또는 installation.json 없음설치 검사를 설치보다 먼저 실행한 상태입니다. ZIP을 모두 압축 해제하고 1-INSTALL.cmd에서 INSTALLATION SUCCESS를 확인한 뒤 2-TEST.cmd를 실행합니다.
installation.json부터 모든 항목이 빨간색이전 0.3.0 검사기에서 설치 전 검사를 실행하면 나타나는 화면입니다. 새 패키지에서는 TEST NOT STARTED로 표시됩니다. 먼저 1-INSTALL.cmd를 실행하십시오.
[FAIL] 표시doctor-report.json과 설치 창의 오류 문구를 함께 전달해 점검을 요청합니다.

8. 제거 방법

3-UNINSTALL.cmd를 더블클릭하고 질문에 Y를 입력합니다. 다른 MCP 설정은 유지합니다. 같은 이름의 항목이 설치 전에 있었다면 원본을 복원하고, 설치 후 사용자가 바꾼 항목은 제거하지 않습니다. 설치 파일은 복구 가능한 백업 위치로 이동합니다.

-Clients Cursor처럼 일부 연결만 제거하면 공유 실행 파일과 한글 보안 등록은 남은 AI를 위해 유지됩니다. 마지막 관리 클라이언트를 제거할 때만 payload와 활성 installation.json을 백업으로 옮깁니다.

백업과 로그까지 모두 제거하려는 숙련 사용자만 PowerShell에서 다음 명령을 실행합니다.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-DocBridge.ps1 -RemoveHwpSecurity -RemoveData

9. 개인정보와 보안

DocBridge MCP 서버는 이 PC에서 로컬 프로세스로 실행되며 별도의 DocBridge 웹 서버가 필요하지 않습니다. 다만 문서 내용을 AI에 보내는 범위와 저장 정책은 사용하는 Codex·Claude·Kimi·Cursor 계정 및 회사 정책에 따릅니다. 개인정보, 계약서, 보안 도면 등 민감한 자료는 조직 규정을 먼저 확인하십시오.
